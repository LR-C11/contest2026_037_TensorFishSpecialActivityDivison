# 设备时间与语音请求修复（0.19.1）

## 确认的问题

语音录音结束后，FlowDesk 会等待可信时间，再发起保留证书校验的 HTTPS 请求。`NTP refresh ... start=435` 代表后台任务已创建，不代表取得时间样本；超时后显示“设备时间尚未同步”。

实际 SDK 的 `apps/netutils/ntpclient/ntpclient.c` 在采样前要求 `netlib_check_ipconnectivity(NULL, 1, 1) > 0`。该检查依赖编译期固定 DNS 地址 `CONFIG_NETDB_DNSSERVER_IPv4ADDR`，而当前配置没有这个选项。即使 DHCP 提供了可用 DNS，检查仍直接失败，所有 NTP 采样被跳过。即使配置固定地址，ICMP 不通也不能证明 NTP 不通。

手动校准原路径与 NTP 重启共用互斥锁，后台停止或启动 NTP 时会阻塞校准标记；原时间检查还先读取 NTP 状态、再读取手动标记。源码层面存在阻塞条件，但无法仅凭已有日志确认用户真机当次失败是否完全由此引起。本轮一并移除这些阻塞关系，增加实际时钟读回核验和可辨识日志。

## 修改

- SDK 直接尝试 NTP 采样，继续保留 DNS 解析、UDP 超时、响应来源及报文校验；采样之间响应停止请求。
- `dm_wifi_set_manual_time()` 统一执行时间范围校验、写时钟、读回核验和手动确认。设置或读回失败不返回成功，并记录原因。
- 语音 HTTPS、提醒和日期显示统一采用同一可信时间判断；本次开机手动校准成功后，先认可手动标记，无需等待 NTP 状态锁。
- NTP 停止和启动不再占用手动校时的状态锁。只在首次选择应用的服务器列表时停止原任务；后续重试保留正在采样的任务，检查间隔120秒。
- 校时等待结束时再检查一次，避免正好在截止边界完成的手动校准被遗漏。
- 页面成功提示改为“本次开机已校准，可使用语音聊天”。日志失败信息增加 `manual`、`seed_only`、年份和样本数，区分未应用校准与重启恢复旧时刻。

当前板级配置没有启用 RTC。保存文件只保存当时的时间，不能计算断电期间的时长。因此，重启后恢复的时刻仍仅作为时间种子，需要实际 NTP 成功或重新手动校准；不能把旧保存时间直接视为当前准确时间。TLS 证书校验保持启用。

## 本机位置与编译

应用源码已同步到 `/home/lrc/vela/vendor/allwinnertech/apps/flowdesk`；SDK 修复已直接写入 `/home/lrc/vela/apps/netutils/ntpclient/ntpclient.c`。其他环境需要另外应用 `docs/patches/sdk-ntp-direct-query.patch`，位置和步骤见《SDK补丁说明.md》。本机已经应用，不要重复应用。

使用原 Gemini-S1 `nsh_minidisplay` 配置增量编译即可，无需 `distclean`。本轮没有执行固件编译、打包或刷机，由用户自行完成。

## 验证与观察点

44组宿主回归测试通过。新增或扩展测试覆盖：实际 SDK 采样循环不依赖 ICMP/固定 DNS、停止采样、时钟写入失败和读回失败、手动确认跨线程被语音检查接受、NTP 锁不阻塞校准标记、重试不打断采样、等待截止边界、页面按后台返回值显示成功或失败、无 RTC 重启恢复旧时刻仍需重新确认。

测试没有连接真实 NTP、ASR 或聊天服务；没有将固件刷入设备，不等同于真机语音验证。

编译新固件后，应用版本为0.19.1。点击“应用时间”成功时应看到：

```text
[deskmate-wifi] manual clock accepted epoch=... seed_saved=...; HTTPS clock ready
```

若设置失败，串口会出现 `manual clock set failed rc=...` 或 `manual clock readback failed`。若云端请求前仍被时间检查阻止，应保留完整的 `clock not ready; status=... samples=... year=... manual=... seed_only=...` 日志用于继续定位。
